Overview

Git is a free and open source distributed version control system designed to handle everything from small to very large projects with speed and efficiency.

Git is easy to learn and has a tiny footprint with lightning fast performance. It outclasses SCM tools like Subversion, CVS, Perforce, and ClearCase with features like cheap local branching, convenient staging areas, and multiple workflows.

Useful commands

Display the state of the working directory and the staging area

git status

Add all the changed files to the staging area

git add .

Add an ignore file to the staging area

git add -f <file1> <file2> ...

Create a commit

git commit -m "message"

Create a new branch

git checkout -b new_branch

Switch to a different branch

git checkout branch_name

Show all the local and the remote tracking branches

git branch -a

Remove a branch

git branch -d branch_name

Upload local repository content to a remote repository

git push

Fetch and integrate changes from a remote repository into your current branch. It combines the functionality of git fetch and git merge.

git pull

Compare two branches - in the gitconfig a difftool has to be set.

git difftool branch1..branch2

Undo the last commit

git reset --soft HEAD~1h

Discard local changes

git reset --hard

Remove unstaged changes

git restore .

Show commits

git log

Show last n commits

git log -n

Show the history of the file

git log --full-history -- file.txt

Stash changes (both staged and unstaged) and revert working directory to match the HEAD commit

git stash push -m "msg"

Stash changes advanced

git stash --keep-index --include-untracked -m "backup link changes"

Create a tag

git tag v1.0

Push a tag

git push origin v1.0

Revert a commit

git revert commit-hash

Preview git clean files

git clean -n -xfd

Clean with exclude

git clean -xfd --exclude=.vscode/

Patches

Create a patch of all the changes

git diff > changes.patch

Create a patch of one file

git diff one-file.txt > changes.patch

Create a patch including non-indexed files

git diff --no-index file1 file2 > changes.patch

Apply patch

git apply changes.patch

Merge

Switch to the target branch

git checkout target_branch

Merge the source branch to the target branch

git merge source_branch

Push the changes

git push

Rebase

Rebase is an alternative to merging. It moves or combines a sequence of commits to a new base commit (the tip of the work branch).

Steps:

  • git checkout base_branch
  • git pull
  • git checkout work_branch
  • git rebase base_branch
  • Resolve conflicts if any
  • git rebase --continue
  • git push -f

Tips

If "Aborting commit due to empty commit message." error occurs (problem with commit message starting with "#"). Use the following configuration to change the comment character in gitconfig.

[core]
  symlinks = false
  autocrlf = false
  commentchar = ";"

After rebasing, pull remote changes with rebase to keep local commits on top of the updated remote branch:

git pull --rebase

Amend a pushed commit

To update the most recent commit that has already been pushed without changing its commit message, stage only the intended files, amend the commit, and push the rewritten history with a lease:

git add <files>
git commit --amend --no-edit
git push --force-with-lease

Replace <files> with the specific paths to include. Check git status before staging so unrelated changes are not included. Coordinate with anyone else using the branch before rewriting its history. --force-with-lease refuses the push if the remote branch has changed since your last fetch.

Reset to a remote branch

git reset --hard discards uncommitted changes to tracked files. Check the repository status and confirm the current branch and target before running it:

git status
git branch --show-current
git reset --hard origin/branch

Replace branch with the intended remote branch name. Save or commit any changes you need before using this command.

Create and push a repository

  1. Create a new empty repository on GitHub. If your project already has files, do not initialize the GitHub repository with a README, license, or .gitignore; add those files locally instead.

  2. From the project directory, initialize Git and make the first commit:

    git init
git status --short
git add .
git status --short
git commit -m "first commit"

    Review the status before committing to ensure you are not adding unwanted files or secrets.

  3. Add the GitHub repository as origin and check the remote:

    git remote add origin https://github.com/<user>/<repo>.git
git remote -v

    Replace <user> and <repo> with your GitHub account and repository name. An HTTPS remote does not use an SSH key. For HTTPS authentication, sign in with Git Credential Manager or GitHub CLI, or use a personal access token when prompted for a password. Do not put a token in the remote URL.

    To authenticate with an SSH key instead, use an SSH remote URL:

    git remote set-url origin git@github.com:<user>/<repo>.git

  4. Push the current branch and set its upstream:

    git branch --show-current
git push -u origin master

    Replace master with the branch name printed by git branch --show-current if your branch is named main or something else. The equivalent command without setting the upstream is git push origin master.
